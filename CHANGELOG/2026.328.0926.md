# 2026.328.0926 — fix(pin): build the element at c5fe3a0, which carries both input fixes

## Summary

Pins the layer at the **merged, tagged** gst-wayland-display `c5fe3a0` (tag `v2026.328.0845`, the merge of opencharly/gst-wayland-display#17) instead of `cda8b20`, and deletes the one check the earlier merge (`64a6f4f`, #12) already made false. Closes opencharly/layer-gst-wayland-display#5.

**This pin is the one that carries the input fixes**, and both are present in the pinned source — verified in the tarball the build downloads, not assumed:

```
$ git show c5fe3a0356be850095763ffce0632dae0ea88968:wayland-display-core/src/comp/input.rs | grep -c under_at_target
5
$ git show c5fe3a0356be850095763ffce0632dae0ea88968:gst-plugin-wayland-display/src/waylandsrc/imp.rs | grep -c navigation_event_or_drop
4
```

- `under_at_target` — the pointer's focus is resolved at its DESTINATION. Without it a pointer that moves ONTO a surface reported the surface it came from, so no `wl_pointer.enter` was emitted and a browser session was pointer-dead for its whole life.
- `navigation_event_or_drop` — a malformed navigation message is dropped with a warning instead of aborting the streaming thread.

- **Pin.** The archive URL, the extracted directory the build enters, and the `BUILD_COMMIT` assertion all move together to `c5fe3a0356be850095763ffce0632dae0ea88968`. They are one value written three times — a mismatch sends the build into a directory that does not exist or records a commit the image was not built from — and the provenance check keeps asserting it exactly, never a 40-hex regex.
- **`gwd-keymap-properties` deleted.** It asserted the fork's `xkb-layout`/`xkb-variant`/`xkb-options` properties. Nothing set them, and #12 removes them: upstream's seat takes its keymap from libxkbcommon's `XKB_DEFAULT_*` via `XkbConfig::default()`. The check's own text said "until opencharly/gst-wayland-display#5 drops them" — this is that cutover, so it would now assert behaviour the element no longer has.
- **`gwd-cuda-device-id-property` stays**, and passes: `--features cuda` is still built, and that property is what proves the NVIDIA zero-copy path is inside the `.so` rather than merely available to be compiled.
- **Docs swept (this diff also carries the earlier `docs(AGENTS)` commit).** `AGENTS.md` no longer lists "the three keymap-property checks" among the plan's evidence, and now says the pinned commit appears **three** times (URL, extracted directory, `gwd-build-commit` assertion) rather than twice. `charly.yml`'s candy `description:` and `README.md` no longer advertise the `xkb-*` properties and smooth-scroll support as things the fork ADDS over upstream — they are dropped, so the text says so, and the README's probe becomes `grep cuda-device-id`. The earlier commit corrects where the layer's checks can run (a build-scope container or a composing pod's bed, not a bed here).

fix has its own proof in the PR that added it (opencharly/gst-wayland-display#17: a real wayland client

exact source.
