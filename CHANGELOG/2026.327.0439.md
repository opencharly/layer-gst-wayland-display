# 2026.327.0439 — feat(layer)!: build GWD from the merged upstream-synced commit with the cuda feature

## Summary

The layer pinned the fork's pre-sync ref (`d1bd382`) with **no feature flag**, so no image ever carried `cuda-device-id` — and the streamer's NVENC path panicked on the property it could not find (opencharly/charly-streamer#16's RCA). This builds the **merged** upstream-synced commit instead, with the CUDA feature on.

- **Pin: `cda8b20`** — opencharly/gst-wayland-display's `stable` HEAD, the merge of upstream `games-on-whales/stable` (Smithay port, NVENC/Vulkan encode, HDR) from `opencharly/gst-wayland-display#6`. A MERGED ref, fetched as an immutable commit tarball by URL — no committed archive, no local staging step.
- **`--features cuda`**: on an NVIDIA render node the element hands CUDAMemory straight to NVENC (`cuda-device-id` present). libcuda still arrives at RUNTIME through CDI; nothing NVIDIA is baked.
- **The Vulkan runtime is installed** (loader + Mesa's radv/anv; NVIDIA's ICD comes through CDI), which is what GWD's NV12/P010 compute conversion and `vulkan=true` need — without a driver for the node it measured *"no usable Vulkan device matches DRM minor 129"*.
- **The checks assert what these actually produce**, not just that files exist: the pinned commit read from the extracted tree's own directory name and compared for **equality** with the pin (a regex over any 40-hex string would pass a swapped archive), `cuda-device-id` on the element, the Vulkan properties, and the Mesa ICDs by the driver library each manifest names.
- **The fork's `xkb-*` properties are still present at `cda8b20`**, so their check stays; dropping them and mapping GstNavigation MouseScroll onto upstream's wheel axis is opencharly/gst-wayland-display#5, which moves this pin when it lands.
- **`README.md` and `AGENTS.md` follow the code**: the README's provenance paragraph now says what the pin actually carries (upstream-tracking fork, its own `xkb-*` and smooth-scroll features, `--features cuda`, Vulkan runtime, CDI-supplied libcuda), and AGENTS.md's "Load these skills first" names `/charly-selkies:kde-cstream` — the skill the KDE replacement ships, which is the consumer whose beds are this layer's runtime gate — in place of the retiring `/charly-distros:omarchy-cstream`, and its check list matches the plan above.

The two skips are by design in this mode, and one of them is the reason the tier is `analysed on a live system` rather than `fully tested and validated`: the mutating build step is already baked into the image being checked, and **`gwd-dmabuf-negotiates` is `context: [runtime]`** — it is the check that exercises the changed DMABuf/CUDA/Vulkan path, and it runs only in a deployed bed. The property checks above prove the feature compiled in; they do not prove the path runs. That bed is `pod-kde-cstream`'s (whose image composes this layer and pod-cstream), and it cannot run before both release.
