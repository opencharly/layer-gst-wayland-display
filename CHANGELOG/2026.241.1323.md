# 2026.241.1323 — feat: gate the DMABuf zero-copy path, and install the VA plugin it needs

## Summary

WP1's gate is that *"a waylanddisplaysrc pipeline negotiates DMABuf into vapostproc and reaches PLAYING"*. It could not run at all here — the candy installed `gstreamer` and `gst-plugins-base` but not `gst-plugin-va`, so the pipeline died with `no element "vapostproc"`. (`mesa`, already in the package list, supplies the VA driver itself.)

This adds `gst-plugin-va` and the gate.

## Why the check looks the way it does

Three details, each of which was **wrong in an earlier revision of this branch** and each of which fails quietly rather than loudly:

**1 — no dollar-brace default syntax, including inside comments.** charly parses a dollar-brace in a command as its *own* runtime variable; finding no binding, it SKIPS the check. Measured on the first revision:

```
SKIP  check a waylanddisplaysrc pipeline negotiates DMABuf into vapostproc and reaches PLAYING
      unresolved variables: CSTREAM_RENDER_NODE:-/dev/dri/renderD128, XDG_RUNTIME_DIR:-/tmp/gwd-gate-rt
```

The bed still reported `PASS (steps=13)`, because a skip is not a failure. A gate that silently stops gating is worse than no gate. The second revision still skipped — the offending syntax was left in a *comment*, which charly scans too.

**2 — `set -e` without `-u`.** Both env vars are legitimately unset in a build container, and the brace-default form that would guard them is the reserved one. With `-u` the check ran and failed on `XDG_RUNTIME_DIR: unbound variable`.

**3 — the assertion is the exact string `GWD-DMABUF-OK`, and a missing render node FAILS rather than skips.** An earlier revision asserted the prefix `GWD-DMABUF`, which a `GWD-DMABUF-SKIP` line would also have satisfied — so the gate would have passed on a host where it never ran. cstream has no software fallback (GWD creates `zwp_linux_dmabuf_v1` only on the hardware path), so an absent node is a configuration error, not a degraded mode.

## How tested

Disposable bed, fresh rebuild, with the check **executing** rather than skipping:

```
PASS  check a waylanddisplaysrc pipeline negotiates DMABuf into vapostproc and reaches PLAYING
      [gwd-dmabuf-negotiates]  exit=0

charly check run check-gwd-layer: PASS (steps=13)
```

Because the assertion now requires `GWD-DMABUF-OK` exactly and an absent node exits 1, that PASS cannot be a vacuous one.

The zero-copy path was also confirmed directly against the built image, where GWD reports the allocation:

```
$ gst-launch-1.0 -q waylanddisplaysrc render-node=/dev/dri/renderD128 num-buffers=30 \
    ! 'video/x-raw(memory:DMABuf),width=1920,height=1080,framerate=60/1' ! vapostproc ! fakesink
INFO waylanddisplaycore::utils::allocator: Creating DMA buffer - DrmFourcc: DrmFourcc(AR30) …
INFO smithay::backend::drm::device::fd: Dropping device: Some("/dev/dri/renderD128")
GWD-DMABUF-OK
```
