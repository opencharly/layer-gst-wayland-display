# 2026.241.2202 — feat: pin the warning-free fork commit

## Summary

Advance the pinned `gst-wayland-display` fork commit from `11e0ec0` (the fork's first commit) to
`d1bd382` (`stable` HEAD), and bump the candy version with it.

Two merged fork PRs sit between them:

- **`gst-wayland-display#2`** — clears the 13 compile warnings the crates emitted. They were
  trivial in isolation (unused imports, three elided-lifetime hidings, an unused `pkg_config` in
  the build script) but this candy **compiles that source inside its own image build**, so every
  consumer's bed inherited them and could not honestly claim charly's R10 zero-warning bar.
- **`gst-wayland-display#3`** — installs the org `pr-validator` in the fork, so changes there are
  gated the same way changes here are.

Fixing them upstream rather than silencing them here is deliberate: a `--quiet` or an allowlist
entry at this end would have hidden *future* warnings from that source too.

## Change classification

**Change class:** candy/box-config — one pinned commit (appearing twice: the `download:` URL and
the extracted directory name it implies) plus the candy `version:`. No Go, no schema, no workflow.

**Verification gate:** a live bed that builds this candy and measures the warning count, since the
whole point of the bump is a diagnostic count.

**Breaking change + rollback:** none — the fork commit only removes warnings; no API, element
name, property or behaviour changes. Rollback is a plain revert.

**Producer → consumer order:** satisfied. `d1bd382` is `stable`'s current HEAD, both fork PRs are
merged, and GitHub serves the archive tarball for it.

**4. The one warning still standing is NOT this candy's, and is being fixed at its source.**
`warning: rust-1:1.98.0-1.1 is up to date -- skipping` — pacman's `--needed` acknowledgement,
which charly already allowlists as `pacman-needed-package-already-current` for `libcap`, `git`,
`pam` and `shadow` in the very same run. It escapes only because the allowance's character class
had no `:` and pacman renders an epoch as `<name>-<epoch>:<ver>-<rel>`. Root-caused and fixed in
**`opencharly/plugin-check#5`**; this bump neither causes nor can fix it, and it is named here
rather than left for a reviewer to find.
